## 二、背景与问题

### 2.1 问题是什么

大学里的琐事都是小事，但**不做就会变成麻烦**。水卡不充值会停水，衣服不洗会发霉，作业不看截止日期会错过，被子不换洗影响健康。

这几件事的共同点：**单件事成本极低（一两分钟就做完），但遗忘的代价很高。**

### 2.2 现有的解决方式为什么失效

| 现在的方式 | 为什么失效 |
| --- | --- |
| 用脑子记 | 记不住；想起了也常常是在做不了的时候（比如躺床上想起水卡没充） |
| 待办类 App | 记进去了但不看。任务列表和功能入口混在一起，待办事项本身不显眼 |
| 微信收藏 / 备忘录 | 只负责存，不负责提醒，等于换个地方忘 |
| 别人提醒（室友 / 同学） | 不可靠，且欠人情 |

### 2.3 结论

**问题不是「没有地方记」，而是「记了之后没有一个恰当的时机被看见」。**

本文档的全部功能设计，都只服务于这一句话。

## 三、目标用户与使用场景

- **目标用户**：在校大学生。第一版以作者本人的真实生活为唯一验收对象，不追求覆盖更多人群。
- **使用时机**：
  - 想起来的时候 → 立刻记下（可能只有 10 秒）；
  - 每天固定的一两个时点 → 打开清单过一遍，决定现在做什么；
  - 做完之后 → 勾掉。
- **具体场景**：
  - 生活类（没有客观到期日）：水卡充值、洗衣服、换洗被子、倒垃圾、谁快过生日了、很久没锻炼了。**这类事什么时候做由用户自己决定**——系统监测不到「水快用完了」，只有你自己知道。所以它们不靠系统判断时机，而是录入时就顺手定一个日子（默认第二天），到点由清单提醒你。
  - 学习类（有硬期限或需连续性）：作业截止、日常学习打卡、考试复习安排。

**这两类场景的共同要求**：打开就能看清要做什么，不能有学习成本。

**使用设备**：本期只做**安卓手机 App**。所有功能必须在安卓手机上完整可用——只有随时能掏出来，才谈得上「想起来的时候立刻记下」。不再支持在电脑上使用（原 Web 版的电脑端能力随路线变更取消）。验收环境为安卓设备；本期以安卓模拟器为准（规格与判定方式见 AC-19、AC-20）。

## 四、核心价值与差异化

**核心价值一句话：打开就看清今天要做什么。**

它不是功能更多的待办工具，而是**信息层级更清楚的**待办工具。

基于 `research.md` 对同类产品的调研，本期明确以下三条为差异点：

| 差异点 | 针对的竞品短板 |
| --- | --- |
| 信息层级 > 功能数量：待办是页面的唯一主角 | 滴答清单、指尖时光都功能齐全，但待办被功能入口和视图切换淹没 |
| 提醒 = 每天固定 1–2 次清点今日，而非临期反复催办 | 反复提醒会让人厌烦，进而无视通知 |
| 无付费引导、无干扰性弹窗 | 付费弹窗是调研产品共有的体验污点 |

**交互细节是信任问题，不是美观问题。** 删除按钮太小、容易误触这类问题，会直接导致用户放弃这个工具，因此在本期功能中按硬性标准约束（见第七节）。

## 五、本期做什么

本期只做下列四条。**不在这张表里的功能，一律不做。**

| 编号 | 功能 | 为什么必须做 |
| --- | --- | --- |
| F1 | 打开即看清要做的事 | 「记了不看」的直接解法，也是相对现有产品的差异点 |
| F2 | 每天固定 1–2 次的清单提醒 | 把「提醒我过一遍今天」这件事落地，是核心价值的唯一载体 |
| F3 | 事项的新增 / 编辑 / 完成 / 删除 | 最小可用闭环，缺任何一个都构不成完整产品；事项内容会变，不能编辑就只能删掉重记 |
| F4 | 周期事项（如「每周洗被子」） | 真实场景里大量琐事是重复发生的 |

**跨功能约束（不是新增功能）**：F1–F4 全部功能必须在安卓手机上可用。它不是与四条功能并列的第五项，而是四条功能共同的判定前提，具体标准见第八节 AC-19 至 AC-20。

## 六、本期明确不做

### 6.1 明确划掉（本期不做，且不排期）

| 不做的事 | 理由 |
| --- | --- |
| 番茄钟、专注计时、白噪音 | 与「琐事提醒」无关，且是竞品功能堆砌的典型来源；加进来就会稀释首页的信息层级 |
| 项目管理类功能（子任务、看板、甘特图、多级优先级） | 技术复杂且场景不需要；一旦引入，界面会重新被堆满，直接否掉第四节确立的差异点 |
| 多人协作 / 共享清单 | 需要账号体系与权限设计，本版验证不了核心价值，属于典型的范围失控 |
| 位置提醒（到教学楼才响） | 依赖系统权限，实现与调试成本高，收益不确定 |
| 复杂的重复规则（如「每月第三个周四」） | 技术复杂，但真实使用频率极低；F4 只做三种基础周期即可覆盖场景 |
| 第三方账号登录体系 | 需要后端与账号权限，本版验证不了 |
| 付费引导与弹窗 | 调研产品共有的体验污点，也是第四节明确要差异化的地方 |
| 课程表导入 | 属于「学习类」的延伸，不是核心痛点的最小验证范围 |
| iOS 版（苹果手机） | 本期只做安卓；做苹果需要 Mac + Xcode + 付费开发者账号，成本远超本期需要 |

### 6.2 有价值但本期不做（排入后续）

| 功能 | 为什么可以后加 |
| --- | --- |
| 多设备同步 | 先验证「愿不愿意用」，再解决「换设备怎么办」；本期数据只存在手机本地、不涉及多端，这是决定，不是遗漏 |
| 分类 / 标签 | 事项数量少时分类是负担 |
| 完成统计与回顾 | 需要先有使用数据才有意义 |

**为什么这份清单要连同理由一起写进文档**：功能不会自己消失，理由会。半年后看到「番茄钟」时，如果只记得「竞品有」，就会想加回来；但如果记得「加它就是重演功能堆砌，等于自己否掉自己的差异点」，就能说服自己不加。**理由的价值在于给未来的自己拦路。**

## 七、功能详述

每条功能包含：它是什么 / 为什么做 / 验收标准。范围或口径需要额外说明时，在「它是什么」之后追加一条定义。

### F1 打开即看清要做的事

- **它是什么**：打开产品后默认进入的页面，直接展示需要处理的事项，不需要任何点击或切换即可看到。
- **清单范围的定义**：首页清单 ＝ 全部未完成事项 ＋ 今天已完成的事项。所有事项都带日期，没有客观到期日的琐事在录入时默认取「录入日的次日」（见 F3）。**已经到期但还没做的事项继续留在清单里，不会消失**——否则就等于回到「记了不看」。
- **为什么做**：对应 2.3 的结论——问题在于「没有一个恰当的时机被看见」。首页就是那个时机。
- **验收标准**：
  1. 打开后默认进入事项列表，首屏内至少可见 3 条未完成事项，不需要点击或切换。
  2. 首屏可见元素只包含四类：标题、事项列表、新增入口、提醒设置入口；不含功能宫格、横幅、推广位、统计图等任何其它模块。
  3. 未完成事项与已完成事项在视觉上可一眼区分，且未完成事项默认排在已完成事项之前。
  4. 事项数量超过一屏时允许滚动，但未完成事项始终排在已完成事项之前，不会因为滚动而被藏到后面。
  5. 已经到期但未完成的事项，第二天打开时仍在未完成区内，且排在未到期事项之前。

### F2 每天固定 1–2 次的清单提醒

- **它是什么**：每天在固定时刻提醒「过一遍今天的清单」，而不是提醒某一条事项该做了。
- **为什么做**：对应第三节差异点二。反复催办会让人无视通知，而把决策权交回给用户才有效。
- **验收标准**：
  1. 提醒时刻可修改，默认 08:00 与 20:00；每天按当前设定的时刻各触发一次，一天合计不超过 2 次。
  2. 提醒内容是当日清单的概览，不包含「请立即完成某一条」这类指令性文案。
  3. 同一条事项在同一天内不会被重复推送。
  4. 当天全部事项已完成时，晚间那一次提醒不推送。

### F3 事项的新增 / 编辑 / 完成 / 删除

- **它是什么**：最小可用闭环——能记下、能改、能勾掉、能删掉。
- **为什么做**：缺任何一个都构不成完整产品；同时这是 3.1 中唯一直接触碰交互细节的功能，需要按硬性标准约束。生活里的事项内容经常在变（「洗衣服」变成「洗被套」），不能编辑就只能删了重记，这与第四节「交互细节是信任问题」相冲突。
- **验收标准**：
  1. 新增：只需填写标题即可保存，标题为空时不可保存，不设其它必填字段。
  2. 新增时不指定日期的事项，日期自动取「录入日的次日」（今天录的明天做），且用户可随时改期。
  3. 编辑：任意一条已有事项都可修改标题；修改后清单内立即显示新内容，且不产生新条目。
  4. 完成：标记完成后该事项在 3 秒内仍可见，且可撤销。
  5. 删除：必须有二次确认或 3 秒内可撤销，不做无提示的直接删除。
  6. 删除、编辑与完成的可点击区域不小于 44×44 dp，避免误触。
  7. 完成操作通过点按**事项整条框**触发，不设勾选圆圈；滑动或长按不触发完成（位移 > 10 dp 或按住 > 500 ms 即作废）。

### F4 周期事项

- **它是什么**：可以设置重复周期的事项，完成后自动进入下一个周期，不需要重新录入。
- **为什么做**：真实场景中「洗被子」「倒垃圾」这类事项是重复发生的，每次重录会直接导致放弃使用。
- **验收标准**：
  1. 支持「每天 / 每周 / 每月」三种周期，不支持更复杂的重复规则（与 6.1 一致）。
  2. 周期事项完成后自动生成下一次日期，且同一周期内不产生重复条目。
  3. 周期事项与单次事项出现在同一个清单里，不需要切换到另一个页面查看。

## 八、验收标准汇总

本节是全部功能验收标准的汇总表，后续每一天的开发成果都按此表逐条对照判定。

**判定规则：每条标准只能给出「通过」或「不通过」，不接受「基本可以」这类中间结论。**

| 编号 | 所属功能 | 验收标准 | 判定方式 |
| --- | --- | --- | --- |
| AC-1 | F1 | 打开后默认进入事项列表，首屏内至少可见 3 条未完成事项，不需要点击或切换 | 手机打开首页，数首屏可见的未完成条数 |
| AC-2 | F1 | 首屏可见元素只有标题、事项列表、新增入口、提醒设置入口四类 | 逐个点数首屏上的元素类型 |
| AC-3 | F1 | 已完成事项有删除线或灰度处理，且全部排在未完成事项之后 | 目视确认样式与排序（任一不符即不通过） |
| AC-4 | F1 | 事项数量超过一屏时，未完成事项始终排在已完成事项之前 | 造 10 条以上事项后滚到底部确认排序 |
| AC-5 | F1 | 已到期但未完成的事项，第二天仍出现在未完成区，且排在未到期事项之前 | 造一条昨天到期的事项，次日打开确认 |
| AC-6 | F2 | 提醒时刻可修改，默认 08:00 与 20:00；每天触发不超过 2 次 | 修改一次时刻后跨天记录触发次数（需跨天验证，最长 1 天） |
| AC-7 | F2 | 提醒内容为清单概览，无指令性文案 | 检查提醒文案 |
| AC-8 | F2 | 同一事项同一天不重复推送 | 查看当日推送记录 |
| AC-9 | F2 | 当日事项全部完成时，晚间提醒不推送 | 造一个全部完成的日期验证（需跨天验证，最长 1 天） |
| AC-10 | F3 | 只有标题为空时不可保存，无其它必填项 | 分别提交空标题与仅标题两种输入 |
| AC-11 | F3 | 新增时不指定日期，保存后日期自动为录入日的次日 | 今天新增一条不填日期的事项，确认日期是明天 |
| AC-12 | F3 | 任意已有事项可修改标题，保存后清单内立即显示新内容 | 修改一条事项标题后查看清单 |
| AC-13 | F3 | 编辑前后条目数量不变，不产生新条目 | 编辑前后对比清单条数 |
| AC-14 | F3 | 完成操作 3 秒内可撤销 | 完成后立即尝试撤销 |
| AC-15 | F3 | 删除有二次确认或 3 秒内可撤销；删除、编辑、完成按钮可点区域不小于 44×44 dp | 执行一次删除并尝试挽回；测量三个按钮尺寸 |
| AC-16 | F4 | 支持每天 / 每周 / 每月三种周期设置 | 分别创建三种周期事项 |
| AC-17 | F4 | 周期事项完成后自动生成下一次且不重复 | 完成一次周期事项后查看清单 |
| AC-18 | F4 | 周期事项与单次事项同屏显示 | 目视确认同一列表 |
| AC-19 | 全局约束 | 在 360–430 dp 宽度区间的安卓机型上无横向滚动、文字不被裁切，列表完整可读 | 在安卓设备上目视确认（本期模拟器为 411 dp）；条件允许时换第二台机型对比 |
| AC-20 | 全局约束 | 新增、编辑、完成、删除四个操作在安卓手机上均可点按完成 | 在安卓设备上依次执行四个操作（本期用模拟器） |
| AC-21 | F3 | 完成操作通过点按事项整条框触发，不设勾选圆圈；滑动或长按不触发完成（位移 > 10 dp 或按住 > 500 ms 即作废） | 点按整条框确认完成；再尝试滑动与长按，确认均不触发完成 |

## 九、成功指标与风险

### 9.1 怎么算做成了

本期不做数据埋点，只用作者本人的实际使用情况判断：

1. 上线后连续 7 天，每天至少主动打开清单 1 次。
2. 连续 7 天内，因为遗忘而错过的事不超过 1 件。

若两条都不成立，说明核心价值未被验证，应回到第三节重新审视场景，而不是继续加功能。

### 9.2 已知风险

| 风险 | 影响 | 本期应对 |
| --- | --- | --- |
| 提醒依赖安卓通知权限，权限被拒时提醒失效 | F2 完全失效，核心价值无从验证 | 权限不可用时，改为打开产品时给出显式提示，不做静默失败 |
| 安卓系统的后台限制（各厂商省电策略）可能让提醒延迟或漏触发 | F2 提醒不稳定，核心价值受损 | 引导用户把本 App 加入电池优化白名单（不做静默失败）；验收时在安卓设备上实测一次跨天提醒（模拟器可直接改系统时间，便于验证） |
| 事项数量持续增长，首屏被撑满 | 影响「打开就看清」的体验，但不影响可用性 | 未完成事项始终排在已完成之前，并保证首屏至少可见 3 条未完成事项（AC-1） |
| 数据只存在手机本地，卸载 App 或清除应用数据会全部丢失 | 换手机 / 重装后事项全没了 | 本期接受；若实际使用中被这条绊到，说明同步需求已被验证，届时按 6.2 补做 |
