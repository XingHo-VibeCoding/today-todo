|---|---|

| 方法 | 本期只有 `GET`（只读） |

## 四、接口清单

### 4.1 `GET /api/health` —— 健康检查

**用途**：确认「云端这条链路是活的」。它不读数据、不写数据，只回答「服务在不在线、跑的是哪一版」。

**请求**

```
GET https://today-todo-d7gn8y38a913633e2-1490344733.ap-shanghai.app.tcloudbase.com/api/health
```

无参数、无请求体。

**成功响应**：HTTP `200`

```json
{
  "ok": true,
  "service": "today-todo",
  "version": "0.1.0",
  "serverTime": "2026-10-12T11:37:09.677Z"
}
```

| 字段 | 类型 | 含义 |
|---|---|---|
| `ok` | boolean | 固定 `true`。服务能返回就说明链路通 |
| `service` | string | 固定 `today-todo`。用于确认打到的是本项目 |
| `version` | string | 接口版本号，与云函数 `package.json` 的 `version` 同步 |
| `serverTime` | string | **服务端时间**（ISO 8601 / UTC） |

**`serverTime` 是这条接口唯一的「活证据」**：它由云端那台机器现算，不是浏览器缓存里的旧值。打开页面时把这个时间和手机上的时间对一下 —— 差几秒属正常（一个是 UTC、一个是本地时区），显示的是几小时前的旧时刻则说明看到的是缓存。

**失败响应**：本期未定义错误信封。已知的错误形态来自平台而非本函数：

| 现象 | 含义 |
|---|---|
| `{"code":"INVALID_ENV"}` + 404 | 环境 ID 或域名拼错（**先怀疑这一条**） |
| HTTP 418、0 字节 | 打到了静态网站托管的空空间（`tcloudbaseapp.com`），不是本接口的域名 |
| 浏览器显示「页面访问提示」 | 正常拦截页，点「确定访问」即可 |

## 六、如何自验（都在本机可复现）

**命令行**（Windows Git Bash）：

```bash
curl -s -A "Mozilla/5.0 (Windows NT 10.0; Win64; x64) Chrome/140.0.0.0 Safari/537.36" \
  "https://today-todo-d7gn8y38a913633e2-1490344733.ap-shanghai.app.tcloudbase.com/api/health"
```

期望：HTTP 200 + 上面那段 JSON。

**浏览器**：粘贴同一地址 → 若有「页面访问提示」先点「确定访问」→ 看到 JSON。**截图时把地址栏一起截进去。**

**换设备换网络**：手机断开 Wi-Fi、用蜂窝流量再打开一次。**只有这一步能证明它真的在公网** —— 在自己电脑上打开成功是假阳性（localhost、缓存、本机代理都能骗人）。
