## 一、要解决的问题

### 1.1 一句话

大学里的琐事都是小事，但**不做就会变成麻烦**；现有工具要么记不住，要么记了不看。

### 1.2 谁用、什么场景

面向在校大学生，先以我自己的真实生活为准。

**生活类（无固定日期、全靠想起来）**

- 水卡该充值了
- 该洗衣服了 / 该换洗被子了
- 垃圾该倒了
- 谁快过生日了
- 很久没锻炼了

**学习类（有硬期限或需要连续性）**

- 作业什么时候截止
- 日常学习打卡
- 考试复习的安排

这两类的共同点：**单件事成本极低（一两分钟就做完），但遗忘的代价很高**（停水、发霉、错过截止、身体走形）。它们既不是"项目"，也够不上"日程"，所以现有工具都不太在意它们。

### 1.3 现在靠什么凑合，为什么不够

| 现在的方式       | 为什么失效                           |
| ----------- | ------------------------------- |
| 用脑子记        | 记不住；想起了也常常是在做不了的时候（比如躺床上想起水卡没充） |
| 待办类 App     | 记进去了但不看。任务列表和功能入口混在一起，待办事项本身不显眼 |
| 微信收藏 / 备忘录  | 只负责存，不负责提醒，等于换个地方忘              |
| 别人提醒（室友/同学） | 不可靠，且欠人情                        |

**结论：问题不是"没有地方记"，而是"记了之后没有一个恰当的时机被看见"。**

## 二、同类产品比较

### 2.1 比较维度（固定五维，便于横向对比）

1. **目标用户与场景**——给谁、在什么时候用
2. **解决方式**——怎么记录、怎么提醒
3. **亮点**——哪一点做得好
4. **短板**——用起来最别扭的地方
5. **与我的差异**——我打算做得不一样的那一处

### 2.2 产品 A：滴答清单（TickTick）【亲测】

- **目标用户与场景**：通用人群，从个人待办到轻度团队协作都覆盖。【资料】
- **解决方式**：任务清单 + 日历视图 + 习惯打卡 + 番茄钟 + 倒数日，支持多级提醒、微信提醒、多平台实时同步，可用自然语言输入日期。【资料】
- **亮点**：覆盖的场景确实全——我列的琐事几乎每一类它都有对应功能；跨平台同步可靠。【资料】
- **短板（我的亲测结论）**：
  - 页面不够直观，**各种功能堆砌**，要找一个东西很费劲；
  - 待办事项**不够显眼**，被功能入口和视图切换淹没；
  - 删除待办项的按钮做得**很小，容易误触**；
  - 会**弹出付费窗口**，打断操作、影响体验。
- **与我的差异**：我要的是一个"打开就能看清今天要做什么"的界面，而不是一个需要学习的功能集合。

### 2.3 产品 B：指尖时光【亲测】

- **目标用户与场景**：学生与上班族，做日程规划与习惯自律。【资料】
- **解决方式**：日程/待办清单 + 习惯打卡 + 番茄专注（含白噪音）+ 时光足迹统计 + 倒数日 + 课程表导入 + 桌面小组件，设有多轮提醒与云端同步。【资料】
- **亮点**：学生场景考虑得多（课程表、桌面小组件能不用打开 App 就看到内容）。【资料】
- **短板（我的亲测结论）**：
  - 与滴答清单同样的毛病：**功能堆砌，页面不直观，找东西费劲**；
  - 记忆点分散在日历、打卡、专注、统计等多个页面，**"待办"不是主角**。
- **与我的差异**：功能数量不是竞争力。**信息层级 > 功能数量**。

### 2.4 这部分改变了我的想法

**改变一：功能多不等于好用，反而是待办被淹没的原因。**  
我原以为做这类工具要尽量多做功能（日历、打卡、番茄钟、统计……），做得越全越有竞争力。看完滴答清单和指尖时光之后我改了：**这两款都把功能做全了，结果待办本身反而变得不显眼。** 信息层级比功能数量重要。

**改变二：提醒不是越准越好——"到点反复提醒"是错的用法。**  
我原来以为提醒的价值在于"准时"。现在我认为，对这类琐事，每次临到要做的时候反复提醒反而是噪音，会让人厌烦、进而无视通知。  
**正确的做法是：每天固定一到两次，提醒我"过一遍今天有哪些事要做"**——不是催我立刻去做某一件，而是把决策权交回给我。

**改变三：交互细节会直接决定用不用它。**  
删除按钮太小、误触、弹付费窗口——这些不是"小瑕疵"，而是会让我直接放弃这个工具的原因。**它是信任问题，不是美观问题。**

## 三、本期不做

把想到的功能按三档切开。**必须做**保证核心价值能被验证，**本期不做**保证第一版能做完。

### 3.1 必须做（不做就无法验证核心价值）

| 功能              | 理由                         |
| --------------- | -------------------------- |
| 一屏看清"今天/近期要做的事" | 这是"记了不看"的直接解法，也是相对现有产品的差异点 |
| 每天固定 1–2 次的清单提醒 | 改变一与改变二落地的唯一方式             |
| 新增 / 完成 / 删除事项  | 最小可用闭环                     |
| 周期事项（如"每周洗被子"）  | 我的场景里大量琐事是重复发生的            |

### 3.2 可以后加（有价值，本期不做也不影响使用）

| 功能      | 可后加的理由                 |
| ------- | ---------------------- |
| 多设备同步   | 先验证"愿不愿意用"，再解决"换设备怎么办" |
| 分类/标签   | 事项数量少时分类是负担            |
| 完成统计与回顾 | 需要先有使用数据才有意义           |

### 3.3 本期不做（明确划掉，附理由）

| 不做的事                      | 理由                             |
| ------------------------- | ------------------------------ |
| 番茄钟、专注计时、白噪音              | 与"琐事提醒"无关，且是竞品功能堆砌的典型来源        |
| 项目管理类功能（子任务、看板、甘特图、多级优先级） | 技术复杂 + 我的场景不需要；一旦引入就会重新把界面堆满   |
| 多人协作 / 共享清单               | 需要账号体系与权限设计，本版验证不了             |
| 位置提醒（到教学楼才响）              | 依赖系统权限，实现与调试成本高                |
| 复杂的重复规则（如"每月第三个周四"）       | 技术复杂，但真实使用频率极低                 |
| 第三方账号登录体系                 | 需要后端与账号权限，本版验证不了               |
| 付费引导与弹窗                   | 弹窗是所有我调研产品共有的体验污点，也是我明确要差异化的地方 |
| 课程表导入                     | 属于"学习类"的延伸，不是核心痛点的最小验证范围       |
| iOS 版（苹果手机）                | 本期只做安卓；做苹果需要 Mac + Xcode + 付费开发者账号，成本远超本期需要 |
