## 第 8 条：从发现到修复（本轮核心产出）

### 首轮为什么不通过

修复前，代码取已完成列表是：

```dart
final done = list.where((t) => t.done).toList()..sort(...);   // 只看 done，不看日期
```

**只要 `done=1` 就显示**，所以历史上完成过的事项全部留着。首轮截图 `05-done.png` 显示的 5 条日期为 10月3日 / 昨天 / 9月23日 / 9月22日 / 9月18日 —— **没有一条是今天**。

而 `docs/PRD.md` 第 134 行（v1.0 起就有的原文）写的是：

> **清单范围的定义**：首页清单 ＝ 全部未完成事项 ＋ **今天已完成的事项**。

**实现与文档从 Day 8 起就不一致**；筛选只是把这条老偏差照了出来。

### 更深一层：PRD 自己内部就有两处互相打架

| 位置 | 说法 | 与（修复前的）实现 |
| --- | --- | --- |
| PRD 第 134 行（F1 清单范围） | 未完成 ＋ **今天**已完成 | 不一致 |
| 第五节 F5「为什么做」 | 已完成区会**随使用天数增长**占走首屏空间 | 一致（但此理由只在「累积显示」下成立） |

这两句**只有在其中一句是错的前提下才能共存**。F5 的立项理由照的是实现的行为（累积），而第 134 行写的是相反的口径（只今天）。

### 产品口径拍板（2026-09-28）

主人定：**认「今天已完成」为准**，并且——

> 当天标记为已完成的内容，当日留在已完成区，**次日自动清空**；清空时间点为**凌晨 4:00**（跨过 4 点即算新的一天）。

### 实现（两处文件）

| 文件 | 改动 |
| --- | --- |
| `lib/db.dart` | `tasks` 表加 `archived INTEGER NOT NULL DEFAULT 0`；新建一行式 `app_state(key, value)` 表存「上次清空时刻」；`_open()` 对老库跑手写迁移（`PRAGMA table_info` 查列，缺则 `ALTER TABLE`）；新增 `_purgeIfNeeded()`，在 `loadTasks()` 开头调用 —— 跨过凌晨 4:00 则 `UPDATE tasks SET archived=1 WHERE done=1 AND archived=0`，并写回新清空点。**`setDone` 未改** |
| `lib/main.dart` | 显示条件一行：`list.where((t) => t.done && !t.archived)` |
